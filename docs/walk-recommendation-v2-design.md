# 산책 추천 점수 세분화와 운영 반영 설계

2026년 10월 6일 기준으로 운영 반영, 추천 점수 세분화, 빠른 지역 전환의 조회 안정화를 설계한다. 기존 24시간 비교·산책 구간 평가·위험 제외·시간 묶기를 유지하면서, 같은 100점이 반복되는 계산을 연속 감점으로 바꾼다. V2 계산과 조회 제어를 실행 코드에 적용했다. 아래 기준은 구현과 테스트의 공통 규칙이며, 검증 결과는 마지막 절에 기록한다.

## 현재 점수의 한계와 선택한 계산

현재 `calculatePetWalkIndex`는 체감온도 5~26℃, 습도 80% 미만, 풍속 7m/s 미만, UV 8 미만, 강수확률 40% 미만에 넓은 무감점 구간을 둔다. AQI도 구간별 고정 감점이다. 예를 들어 18℃와 24℃, 강수확률 0%와 35%가 같은 점수가 될 수 있다. `getDogHeatStatus`는 20℃ 초과부터 주의를 표시하는 반면 점수는 26℃까지 감점하지 않아 설명도 일치하지 않는다.

V2는 100점에서 6개 항목의 감점을 빼는 방식을 사용한다. 아래 최대 감점의 합은 100점이다. 넓은 계단 대신 기준점 사이를 선형으로 연결한다. 비교한 하루의 최고점을 무조건 100점으로 만드는 상대 평가나, 순위를 벌리기 위한 임의 가점은 사용하지 않는다.

아래 수치와 개인화 계수는 초기 서비스의 비교 기준이다. 반려견의 임상 안전 기준이나 안전 보장으로 표시하지 않는다. 실제 예보에서 점수·추천 제외율·추천 이유를 확인한 뒤 조정한다.

| 항목     | 최대 감점 | 표시할 이유                           |
| -------- | --------- | ------------------------------------- |
| 체감온도 | 35점      | 더위·추위 부담, 프로필 보정 포함      |
| 강수     | 25점      | 비 가능성·예상 강수량·비 또는 눈 상태 |
| 대기질   | 15점      | AQI 상승                              |
| 바람     | 10점      | 풍속 증가                             |
| 자외선   | 10점      | UV 증가                               |
| 습도     | 5점       | 높은 습도                             |

체감온도는 이미 습도·풍속의 영향을 포함하는 값이므로 두 항목의 추가 감점은 작게 제한한다. US AQI는 여러 오염물질 지수의 최대값을 사용하는 종합 대기질 지표다. PM2.5는 보조 정보로 표시하고 별도로 더 감점하지 않는다. [Open-Meteo 대기질 자료 정의](https://open-meteo.com/en/docs/air-quality-api).

### 항목별 기준점

각 괄호는 `(입력값, 감점)`이다. 범위 밖은 가장 가까운 끝 감점으로 제한한다. 유효성 검사는 계산 전에 수행하며 null·NaN·문자열을 숫자 0으로 바꾸지 않는다. 강수확률·습도는 0~100, 풍속·강수량·UV·AQI는 0 이상인 유한 수여야 한다.

| 계산 키         | 단위              | 기준점                                                                             |
| --------------- | ----------------- | ---------------------------------------------------------------------------------- |
| temperature     | ℃                 | (-5,35), (0,25), (5,15), (10,5), (15,0), (20,0), (23,6), (26,18), (28,27), (30,35) |
| rainProbability | %                 | (0,0), (20,2), (40,6), (60,12), (80,18), (100,25)                                  |
| rainAmount      | mm/시간 예보 구간 | (0,0), (0.1,3), (0.5,8), (1,12), (2.5,20), (5,25)                                  |
| airQuality      | US AQI            | (0,0), (25,0), (50,2), (75,5), (100,9), (125,12), (150,15)                         |
| wind            | m/s               | (0,0), (2,0), (4,2), (7,6), (10,9), (12,10)                                        |
| ultraviolet     | UV                | (0,0), (2,0), (3,1), (5,3), (6,4), (8,7), (11,10)                                  |
| humidity        | %                 | (0,0), (60,0), (70,1), (80,3), (100,5)                                             |

기준점 `(x0,p0)`와 `(x1,p1)` 사이에서는 `p = p0 + (p1-p0) × (x-x0)/(x1-x0)`으로 계산한다. 예를 들어 체감온도 22℃는 4점, 24℃는 10점 감점이다.

강수 감점은 `max(확률 감점, 강수량 감점, 날씨 상태의 최소 감점)`이다. 같은 비를 확률·양·상태로 세 번 합산하지 않는다. 최소 감점은 Drizzle 8점, Rain·Snow 15점, Thunderstorm 25점, 나머지 알려진 상태는 0점이다. WMO 51~55는 Drizzle로 구분하고, 56·57·66·67은 어는 비 제외 기준을 유지한다.

계산은 원래 정밀도로 수행하고 최종 총점만 정수로 반올림한다. 항목별 상세 감점은 소수 첫째 자리까지 표시한다. 따라서 상세에는 반올림으로 합계가 조금 다를 수 있음을 설명하고, 동일한 정수 총점은 동점을 허용한다. 예보의 정밀도보다 세밀한 차이가 확정적 우열처럼 보이지 않게 한다.

### 개인화

검증해서 저장한 프로필이 있을 때만 견종·털 길이·체중의 체감온도 참고 보정을 적용한다. 프로필이 없으면 일반 체감온도를 쓴다. 이름 입력 여부나 저장 전 초안으로 점수가 달라지지 않아야 한다.

기존 보정은 20℃에서 더위 가산과 추위 감산이 한 번에 바뀌므로 보정도 연속적으로 바꾼다. 기존 최대 가산인 단두·북방 견종 3℃와 긴 털 2℃, 최대 감산인 7kg 이하 2℃와 짧은 털 1℃는 초기 참고값으로 유지한다. 더위 가산은 원본 체감온도 15~25℃에서 0~100%로 늘리고, 추위 감산은 15~5℃에서 0~100%로 늘린다. 각 비율은 0~1로 제한하고 보정 계산 중에는 반올림하지 않는다. 예를 들어 더위 비율은 `clamp((원본 체감온도 - 15) / 10, 0, 1)`이다. 화면에 보여줄 보정 온도만 소수 첫째 자리로 반올림한다. 이 보정도 실제 반려견 체온이나 측정 체감온도로 표현하지 않는다.

기존 나이 8점·활동량 6점의 일괄 감점은 온도 감점에 비례하는 방식으로 대체한다. 기본 온도 감점에 `1 + 나이 계수 + 활동 계수`를 곱하고 최대 35점으로 제한한다. 나이 계수는 1세 이하 또는 8세 이상이면 0.15, 그 외에는 0이다. 활동 계수는 활동량 high이며 보정 체감온도가 20℃를 초과하면 0.10, 그 외에는 0이다. 쾌적 구간의 감점 0은 프로필 때문에 깎이지 않는다. 체중·나이 등 저장 검증이 실패하면 부분적인 보정 대신 프로필 오류를 안내한다.

## 점수보다 먼저 적용할 제외 기준

현재 회피 기준을 유지한다. 산책 구간에 뇌우, 어는 비 코드 56·57·66·67, 보정 체감온도 30℃ 이상 또는 -5℃ 이하, 풍속 12m/s 이상, 해당 시간 예보 강수량 5mm 이상, US AQI 151 이상이 있으면 총점과 관계없이 추천에서 제외한다. 예를 들어 다른 항목이 모두 무감점이고 AQI가 151이면 총점은 85점이지만 BEST가 될 수 없다.

원본 정밀도 총점이 60 미만인 경우도 제외한다. 59.6점을 반올림한 60점으로 추천하지 않는다. 60 이상 80 미만은 주의 후보, 80 이상은 좋은 후보로 표시하되, 회피 조건과 자료 부족 표시가 항상 우선한다. 60 미만이며 표시 점수가 반올림으로 60이면 상세에 원본 점수와 기준 미달을 명시한다.

기존 주의 안내도 동일 평가 결과에서 함께 만든다. 보정 체감온도 20℃ 초과 또는 5℃ 미만, AQI 101 이상, UV 6 이상, 풍속 7m/s 이상, 습도 80% 이상, 강수확률 40% 이상·강수량 0 초과 또는 비·눈 상태는 주의 표식이다. 총점이 80 이상이어도 해당 표식이 있으면 주의 조건 있는 후보로 표시한다. 항목 감점과 경고 기준은 같은 평가 함수에 두고 화면이 별도로 수치를 판단하지 않는다.

자료 누락·중복 시각·알 수 없는 날씨는 점수 null, 자료 부족으로 표시하고 추천에서 제외한다. 모든 시간이 제외되면 추천 가능한 시간이 없다는 상태를 유지한다. 위험과 자료 부족이 함께 있으면 각각의 이유를 보존한다.

## 산책 구간과 데이터 시각

출발 후보는 기존처럼 정시, 현재 이후 24시간이며 산책 종료까지 사용자의 가능 시간에 들어와야 한다. 선택한 길이와 한국 시간 해석도 유지한다. 점수를 세분화하기 위해 15분 예보를 보간해서 정밀한 실측 예보처럼 보여주지 않는다. 한국 지역의 15분 자료는 시간별 자료 보간일 수 있다. [Open-Meteo 예보 자료 정의](https://open-meteo.com/en/docs).

Open-Meteo의 강수량과 강수확률은 표기 시각의 이전 1시간을 나타낸다. 08시 값은 07~08시 구간에 대응한다. 온도·풍속·날씨 코드 등 시각 값과 같은 방식으로 행 전체를 한 칸 옮기면 안 된다. [시간별 변수의 유효 시각 정의](https://open-meteo.com/en/docs).

각 산책 시간 구간을 겹치는 정시 블록으로 나눈다. 예를 들어 07:00~08:30은 07~08시, 08~09시 블록을 평가한다. 블록마다 양쪽 경계의 순간 날씨·같은 시각 AQI를 각각 평가하고, 두 평가에는 블록 종료 시각 행의 강수량·확률을 공통으로 적용한다. 둘 중 낮은 점수를 블록 점수로, 전체 블록 중 낮은 점수를 산책 점수로 정한다. 07:00~08:00 종료에서는 08~09시 강수 구간까지 추가하지 않는다. 블록 양쪽 순간 날씨의 회피 조건은 모두 확인한다.

일부만 겹치는 블록의 1시간 강수량을 30분 양으로 나누거나 확률을 시간 비율로 줄이지 않는다. 상세에는 시간 단위 예보의 전체 블록을 확인했다고 표시한다. 기존과 같은 27시간 자료를 사용하며, 마지막 후보의 종료 경계에 필요한 자료가 없으면 제외한다.

출발 당시 점수, 구간 최저점, `max(0, 출발 당시 점수 - 구간 최저점)`인 하락폭을 제공한다. 최저점을 만든 평가의 시각·강수 적용 구간·항목 감점을 함께 보존한다. 서로 다른 시각의 항목별 최대 감점을 합쳐 최저점의 설명으로 쓰지 않는다. 같은 최저점이 여러 번이면 가장 이른 평가를 대표 설명으로 사용한다.

현재 관측 점수와 미래 산책 점수는 구분한다. 현재 관측에는 강수 상태·최근 강수량을 적용하며 제공되지 않은 강수확률은 미제공으로 표시한다. `toWeather`의 고정 rainChance 0과 상세의 hourly[0] 확률 대입을 실제 현재 확률처럼 사용하지 않는다. 예보 점수에서는 해당 강수 구간의 확률·양이 필수다. 현재 관측의 필수 온도·습도·바람·UV·AQI 등이 없으면 부분 합계를 정상 점수로 표시하지 않는다.

## 동점과 추천 시간 묶기

후보 선택은 자료와 회피 기준 통과 → 원본 점수 60 이상 → 표시 정수 점수 높은 순 → 하락폭 작은 순 → 가까운 출발 순서다. 같은 조건을 출발 시각만으로 임의 감점하지 않는다.

최고 표시 점수와 3점 이내인 연속 출발은 실제 조건도 비슷할 때 묶는다. 묶음 전체에서 보정 체감온도 범위 2℃ 이내, 강수확률 15%p 이내, 풍속 2m/s 이내, UV 2 이내, AQI 25 이내를 초기 기준으로 사용한다. 후보의 대표 조건은 구간 전체 체감온도 최솟값과 최댓값, 강수확률·풍속·UV·AQI 최댓값이다. 두 온도 값 각각의 후보 간 범위를 검사한다. 비·이슬비, 눈, 강수 없음의 분류와 주의 표식 집합도 같아야 한다. 한 산책에 여러 강수 분류가 있으면 분류 집합이 같은 후보끼리만 묶는다. 각 블록의 관측값이 아니라 전체 산책 구간 값을 비교한다.

인접 두 후보만 비교해서 서로 다른 조건을 길게 이어 붙이지 않는다. 새 후보를 넣은 묶음 전체가 기준을 만족하는지 검사한다. 위험 시간·자료 누락·시간 단절은 묶음을 끊는다. 끝 시각은 마지막 출발 시각이다. 조건이 같은 07·08·09시는 07~09시 출발 모두 적합으로 표시하고, 총점이 비슷해도 한쪽은 비 예보면 별도 묶음으로 표시한다.

## 화면과 계산 결과의 연결

기존 `petWeather.js`에 순수 평가 함수 하나를 두고 점수·감점·제외 이유를 함께 반환한다. 일반 점수와 개인화 점수 함수는 이 평가 결과의 score를 반환하는 기존 호출용 함수로 유지한다. 현재 관측과 시간 예보의 두 실제 사용 목적을 평가 옵션으로 구분한다. 별도 추천 서버나 외부 AI 호출은 추가하지 않는다.

| 결과                          | 역할                                                                                                   |
| ----------------------------- | ------------------------------------------------------------------------------------------------------ |
| score, unroundedScore         | 표시 정수 총점과 제외 판정에 사용할 원본 총점. 자료 부족이면 둘 다 null.                               |
| deductions                    | 6개 항목의 code·감점·원본 값·단위·설명. 개인화는 온도 항목 안에 포함.                                  |
| blockedReasons, missingFields | 위험 및 자료 부족의 근거.                                                                              |
| eligible, cautionFlags        | 자료·회피 기준·원본 점수 기준을 모두 통과한 경우만 eligible true. 주의 표식은 총점 등급보다 우선 표시. |
| evaluatedAt, rainInterval     | 최저점을 만든 평가 시각과 사용한 강수 구간.                                                            |

`getBestWalkTime`은 각 후보의 최저 평가 결과를 기존 슬롯에 붙인다. 차트, 상세, 개인 플랜은 같은 후보 결과와 같은 가능 시간·산책 길이 옵션을 사용한다. 안내문을 위해 다시 다른 수식을 계산하지 않는다. `getWalkAnalysis`의 감점 이유도 평가 결과에서 만들고, 노면 추정 안내는 별도 참고 정보로 유지한다.

홈의 추천 도시 계산, 상세의 진행 표시, 산책 화면의 점수 props도 함께 갱신한다. null은 0점으로 바꾸거나 다른 숫자와 비교하지 않는다. 도시 추천은 해당 현재 관측 평가가 eligible인 도시만 대상으로 하고, 없으면 선택한 도시 안내 또는 추천 없음 상태를 표시한다. 프로필이 저장된 경우 산책 화면의 점수·더위 상태·감점 이유는 모두 같은 보정 온도를 사용한다. 현재 점수만으로 산책 전체가 안전하다고 안내하지 않는다.

화면은 오늘 07:00 출발 · 30분 · 구간 최저 82점처럼 먼저 요약한다. 현재 관측의 감점 항목을 보여주고 후보 상세에서 최저점을 만든 평가의 6개 항목·예보 시각·최저점·하락폭·제외 이유를 확인한다. 자료 부족이면 숫자 대신 정보 부족을 표시한다. 차트 클릭 외에도 현재 키보드 후보 선택을 유지하고, 색상만으로 추천 여부를 구분하지 않는다. API 상태·프로필 이름·설명은 Vue 텍스트로 렌더링하고 HTML tooltip을 사용하지 않는다.

## 지역 전환 조회 안정화

`WeatherParent.vue`의 검색에는 요청 순번 확인이 이미 있으므로 같은 방식을 상세 조회에 적용한다. `DogWalkView.vue`와 `WeatherDetailView.vue`의 각 화면에서 요청이 시작될 때 순번을 증가시키고 지역 ID를 지역 변수로 고정한다. 요청 결과는 먼저 지역 변수에 받은 뒤 최신 순번일 때만 city에 반영한다. catch와 finally에서도 최신 순번을 확인해 오래된 실패나 로딩 종료가 최신 화면을 변경하지 못하게 한다.

산책 지역 선택 시 URL을 갱신하고, 확정된 route.query.city를 기준으로 조회하는 한 흐름을 사용한다. 성공 응답에서 이전 지역 URL을 다시 쓰지 않는다. 브라우저 뒤로·앞으로 이동도 같은 경로 감시에서 처리하고, 같은 지역을 선택하면 URL 갱신·조회하지 않아 순환 갱신을 막는다. 상세 화면은 route.params.cityId를 같은 규칙으로 처리한다. 새 선택 직후 이전 지역 안내를 숨기고 진행 중 요청을 무효화하되 기존 산책 시간 선택은 유지한다. 최신 요청 실패 시 이전 지역 날씨를 새 지역 날씨처럼 보여주지 않는다.

화면이 종료될 때 순번을 증가시켜 진행 중 응답을 무효화한다. API 함수 전체에 전역 최신 요청 하나를 두지 않는다. 서로 다른 화면의 정상 조회가 서로 취소되지 않아야 한다. 요청 취소는 지금의 정확성 문제 해결에 필수는 아니며, 낭비되는 외부 호출이 실제 확인될 때 추가한다.

| 완료 순서                            | 화면에 남아야 할 결과                              |
| ------------------------------------ | -------------------------------------------------- |
| A 요청 → B 요청 → B 성공 → A 성공    | B 날씨·B URL, A 응답 무시                          |
| A 요청 → B 요청 → A 실패 → B 성공    | B 로딩 중 A 오류를 표시하지 않음, 최종 B           |
| A 요청 → B 요청 → A 성공 → B 실패    | B 오류, A를 B로 표시하지 않음                      |
| A1 요청 → B 요청 → A2 요청 → A1 성공 | A1도 이전 요청이므로 무시, A2 결과만 허용          |
| 조회 중 다른 페이지로 이동           | 종료된 화면의 응답이 현재 URL·화면을 변경하지 않음 |

## 수정과 검증 결과 · 2026-10-06

Vue와 server-renderer는 3.5.43, source-map-js는 1.2.2, postcss-selector-parser는 7.1.6으로 갱신했다. Vue 최소 허용 버전을 3.5.42로 올리고 잠금 파일을 함께 수정했다. 새로운 의존성은 추가하지 않았다. `npm audit --include=dev --audit-level=high`는 알려진 취약점 0건이다.

보안 헤더는 `vercel.json` 한 곳에서 읽어 정상·입력 거절·외부 API 오류·없는 API와 로컬 서버의 예외 응답에 적용한다. API는 no-store를 유지한다. Vercel의 Vite 빌드·잠금 파일 설치·dist 출력 경로를 명시했다. 배포 파일 사전 점검에서 실제 `.env.local`과 `.vercel` 인증 설정은 업로드 대상에서 제외됐다.

실제 운영 별칭은 2026-08-23 배포 `dpl_B7t7CugxpLq5Whes51BLLsX7bY2x`에 연결되어 있었다. 이후 추가한 보안 설정이 운영에 반영되지 않은 상태였다. 기존 Vercel 인증은 만료되어 있었고 이번 점검 중 재로그인을 완료했다. 운영 환경에 두 서버 API 키가 등록된 사실만 확인했으며 값은 출력하지 않았다.

최종 통합 검사에서 민감값 58개 파일 0건, 코드 검사 오류·경고 0건, 테스트 55개, 운영 빌드가 통과했다. 테스트에는 강수 중복 감점 방지, 이전 1시간 예보 적용, 최저점 설명, 프로필 경계의 연속 보정, 실제 조건에 따른 묶음 분리, 두 화면의 이전 성공·실패·로딩 무시와 빠른 B→A 전환·뒤로 가기가 포함된다. 누락 기온·대기질을 0 또는 NaN으로 표시하지 않는 처리도 확인했다.

가짜 외부 응답을 실제 API 처리기에 연결한 로컬 브라우저에서 현재 관측 86점과 더위 주의, 미래 98점 묶음과 다음 날 후보, 뇌우 후보 46점·추천 제외와 해당 평가의 강수 25점 감점, 부산 변경 후 URL과 안내 지역 일치를 확인했다. 이 확인은 실제 날씨 예보의 정확도 검증과 구분한다. 기존 500kB 초과 번들 크기 경고는 남아 있으며 빌드 실패가 아니다.

코드 수정 커밋 `7a76df1c0f6c6e7629043b9224324d512c400cf9`를 한국어 메시지로 푸시했고 [새 원격 Actions](https://github.com/hyun5555/skala-vue/actions/runs/37402127620)의 설치·민감값·코드·54개 테스트·빌드·취약점 검사가 모두 성공했다. 이전 실패 실행은 당시 기록으로 남는다.

Vercel 배포 후보에서 같은 커밋과 Node 24.x를 확인했다. [Vercel CLI의 보호된 배포 조회](https://vercel.com/docs/cli/curl)에서 임시 자동화 우회 토큰이 생성되어, 후보 검사를 마친 뒤 해당 토큰만 폐기했고 기존 배포 보호 설정은 유지됐다. 원격 인증·환경 값을 소스나 문서에 저장하지 않았다.

검증한 후보를 운영 별칭에 반영한 뒤 `https://skala-walkie-weather.vercel.app`의 루트 200·없는 API 404에 대해 보안 헤더 5개와 API no-store 검사가 통과했다. `/weather/city_01` 직접 접속과 실제 날씨 API는 200이며, 시간별 예보 27개가 반환되고 조회 시점 추천 후보에 누락 평가가 없었다. 운영 브라우저에서도 차트·6개 감점·오늘/내일 후보가 표시되며 콘솔 오류·경고가 없었다.

현재 실제 서울 예보에서는 관측 95점·BEST 99점이었다. 날씨가 비슷하면 높은 점수와 동점을 유지한다. 점수 차이를 강제로 만드는 규칙은 추가하지 않았다. 마지막 화면 검토에서 프로필 미등록 시 일반 기상 체감온도로 평가했음을 명시하고, 페이지 언어 ko와 서비스 제목을 설정했다.

홈의 도시 카드와 지역 비교에 남아 있던 별도 단계식 외출 점수도 제거했다. 카드·홈 요약·지역 비교는 동일한 현재 관측 평가를 사용한다. 지역 비교는 평균 날씨로 만든 가상 점수 대신 실제 추천 가능한 도시 중 최고 점수와 그 도시의 날씨를 보여준다. 85점인 AQI 회피 도시보다 82점인 정상 후보를 추천하고, 모두 회피·정보 부족이면 추천 지역 없음을 표시하는 회귀 테스트를 추가했다. 로컬 브라우저에서 홈 요약·카드·비교의 동일한 86점과 주의 표시, 콘솔 오류·경고 없음을 확인했다.

main 병합은 변경 검토 후 진행한다. 운영은 작업 브랜치의 검증한 배포를 반영한 상태이며, 자동 배포 시 이 수정이 유지되도록 PR에서 main에 반영할 필요가 있다. 번들 크기 최적화와 현재 화면의 시간 설정 저장은 별도 후속 작업이다.
