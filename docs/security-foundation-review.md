# 초기 개발 기반 보안 검토

검토일: 2026-10-06. `codex/refactor-foundation` 작업 트리의 구현을 Application Security Engineer 역할 에이전트가 독립 검토했다. 아래 범위에서 통합을 차단할 신규 보안 문제는 발견하지 못했다. 운영 보안 확인은 별도로 남는다.

## 실제 검토 범위

`docs/development-foundation.md`, 공용 브라우저 저장 함수, 설정·관심 도시·프로필 Pinia store와 `DogWalkGuide.vue`의 호출 흐름을 확인했다. `.github/workflows/quality.yml`, `scripts/check-secrets.mjs`, `scripts/check-deployment.mjs`, `package.json`의 검사 명령과 관련 회귀 검사도 읽었다. 기존 `server-utils.js`의 지역 ID 형식, 서버 오류 로그, 저장 오류를 표시하는 `App.vue`를 관련 근거로 확인했다.

## 구현에서 확인한 보호

1. 저장 데이터는 `{ version: 1, data }` 형식으로 복구한다. 설정은 온도 단위·정밀도만, 프로필은 이름·견종·나이·체중·털 길이·활동량만 새 객체에 담는다. 알 수 없는 필드가 저장 상태에 그대로 복사되지 않는다.
2. 프로필 이름·견종의 길이·제어문자, 숫자의 타입·유한성·범위, 선택값을 검증한다. Vue 일반 텍스트 바인딩을 사용하며 프로필 필드를 HTML로 삽입하지 않는다.
3. 저장소 접근·JSON 파싱·쓰기·삭제 예외를 잡고 값이나 예외 원문을 로그에 출력하지 않는다. 프로필 저장·삭제는 브라우저 작업이 성공한 뒤 상태를 변경한다. 실패한 초안이 저장된 추천값을 덮지 않는다.
4. 기존 버전 없는 유효한 `petWeatherProfile`을 읽고 버전 형식으로 다시 저장한다. 변환 저장이 실패하면 기존 저장값을 남기고 오류를 안내한다.
5. 서버의 외부 API 오류 로그는 서비스 구분과 숫자 상태만 기록한다. API 키·좌표·외부 응답 본문·예외 메시지를 기록하지 않는 기존 동작을 유지한다.
6. CI는 `push`와 `pull_request`에서 실행하고 `contents: read`만 선언한다. `pull_request_target`, 배포, 별도 secret 환경 변수는 없으며 checkout의 자격증명 저장을 끈다. 외부 Action은 커밋 SHA로 고정했다. 검사에 `continue-on-error`가 없고 잠금 파일을 사용하는 `npm ci`, 수정 없는 lint, 회귀 검사, 빌드, 개발 의존성을 포함한 `npm audit`를 실행하도록 구성했다. 실제 Actions 성공 여부는 별도 확인 대상이다.
7. 민감값 검사는 Git 추적 민감 파일과 추적·미추적 소스의 하드코딩 패턴을 확인한다. 일반 파일만 읽고 심볼릭 링크를 따라 로컬 자격증명을 읽지 않는다. 실패 출력은 파일·행·사유만 포함하며 Git·파일 접근 오류도 실패 종료한다. 테스트 파일을 통째로 제외하지 않고 생성한 가짜 패턴으로 검출을 확인한다.
8. 운영 점검은 인증정보·경로·쿼리·fragment가 없는 HTTPS 주소만 받고 루트와 존재하지 않는 API에 GET을 한 번씩 보낸다. 리다이렉트를 따라가지 않으며 키·좌표·응답 본문·실제 헤더값을 출력하지 않는다. 상태·형식·정책 누락과 연결 실패는 실패로 기록한다. 이 요청은 정상 날씨 연동이나 API 남용 방지를 검사하지 않는다.

## 발견 사항과 수정 확인

| 중요도 | 위치와 재현 | 영향 | 최소 수정과 상태 |
| --- | --- | --- | --- |
| 중간 · 개인 데이터 최소화 | 초안의 `favoriteStore.js`가 `geo_` ID를 영속 저장했다. 서버의 `createLocationId`는 검색 지역명과 좌표를 base64url에 담는다. | ID라는 이름으로 지역 좌표까지 저장하게 된다. base64url은 암호화가 아니며 GPS 현재 위치와도 구분해서 설명해야 한다. | **수정 확인:** 고정 `city_01`~`city_06`만 디스크 읽기·쓰기에 허용한다. 검색 지역 관심은 세션에서 유지하고 새로고침 시 사라짐을 안내한다. 회귀 검사가 통과했다. |
| 중간 · 데이터 보존 | 초안의 `readStoredData`에 `{ version: 2, data: ... }`를 넣으면 기본값 반환과 함께 기존 값을 삭제했다. | 새 버전 사용 후 이전 배포로 돌아가면 기존 데이터를 손상 데이터로 오인해 삭제할 수 있다. | **수정 확인:** 미래 정수 버전은 삭제하지 않고 기본값·미지원 안내를 반환한다. 원본 보존 회귀 검사가 통과했다. |
| 낮음 · 저장 검증 | 초안에서 `geo_invalid`가 관심 도시 저장 검증을 통과했다. | 유효한 지역으로 복원되지 않는 관심 항목이 남을 수 있었다. 서버는 자체 검증으로 거절하므로 현재 근거에서 외부 호출 우회는 확인하지 않았다. | **저장 범위 수정 확인:** 디스크의 `geo_` 항목은 허용하지 않는다. 현재 메모리 관심 ID의 문자·길이 검증은 서버의 좌표·형식 검증을 대체하지 않는다. |
| 낮음 · 검사 정확성 | 작성 중인 DevOps 회귀 파일의 가짜 하드코딩 패턴이 저장소 검사에서 3건으로 검출됐다. | 정상 검사의 CI 실패를 유발했다. | **수정 확인:** fixture를 문자열 조합으로 생성하며 검사 파일의 포괄 예외를 추가하지 않았다. 실제 패턴 검출 검사와 저장소 검사 모두 통과했다. |

설정·관심 필터는 저장이 실패해도 현재 화면에서 사용할 수 있고 새로고침 후 마지막 저장값으로 돌아갈 수 있음을 공통 오류로 안내한다. 프로필은 추천을 바꾸는 명시적 저장 동작이므로 성공 전 기존 상태를 보존한다. 이 차이는 개인정보 유출이나 접근 제어 실패로 분류하지 않는다.

## 수행한 검증

실제 운영 키나 사용자 좌표를 읽거나 출력하지 않았다. 메모리 저장소·가짜 키 문자열·격리된 임시 Git 저장소·mock HTTP 응답으로 다음을 확인했다.

1. 초안의 `geo_invalid` 저장 허용과 미지원 버전 삭제를 재현했다.
2. 프로필 저장에서 `QuotaExceededError`를 발생시켰을 때 저장된 프로필이 유지됐다.
3. 프로필 삭제에서 `SecurityError`를 발생시켰을 때 저장된 프로필이 유지됐다.
4. `node --test test/browserStorage.test.js test/petProfileStore.test.js test/stores.test.js test/security.test.js`의 **22개** 검사가 통과했다. 저장소 getter 거부, 손상 데이터 삭제 실패, 미래 버전 보존, legacy 이관·이관 실패, allowlist, 저장·삭제 실패, 기본 도시만 영속화와 기존 서버 로그 마스킹을 포함한다.
5. `node --test test/devopsChecks.test.js`의 **5개** 검사가 통과했다. 민감 파일·패턴 검출과 값 미출력, 안전한 fixture, 비정상 URL 거절, 읽기 요청의 경계, 응답 정책·리다이렉트·연결 실패 처리를 확인한다.
6. `node scripts/check-secrets.mjs`는 **55개 파일, 발견 0건, 종료 코드 0**이었다. 이 결과는 검사 대상 현재 파일과 구현한 패턴에 한정된다. Git 과거 기록, 무시된 로컬 환경 파일, 모든 자격증명 형식과 조합·인코딩된 값은 보장하지 않는다.

독립 검토 에이전트는 실제 GitHub Actions 실행, 운영 URL 호출, 브라우저 UI 검증, 침투 테스트를 수행하지 않았다. 조정자가 수행한 빌드·통합 검사·운영 응답 점검은 조정자의 기록과 구분한다. CI 설정을 읽고 로컬 회귀 검사를 통과한 것을 실제 Actions 성공으로 해석하지 않는다.

## 남은 운영 작업

1. 공개 날씨·지역 검색·장소 API의 공유 요청 제한을 실제 Vercel Firewall 설정과 외부 API 할당량에 맞춰 확인하고 초과 시 `429`를 검증한다. 인스턴스별 메모리 카운터만으로 운영 제한 완료를 선언하지 않는다.
2. 플랫폼 요청 로그에 검색어·URL·장소 조회 좌표가 남는지, 보관 기간과 접근 권한이 무엇인지 확인한다. 앱의 마스킹과 `no-store` 응답은 플랫폼 로그 삭제를 의미하지 않는다.
3. 최신 배포 커밋과 HTTPS 응답의 CSP·프레임 차단·권한 정책·API 헤더를 확인하고 정상 날씨·프로필·장소 화면도 별도로 실행한다.
   조정자의 2026-10-06 운영 점검에서는 메인 GET이 `200`이었지만 CSP·`X-Frame-Options`·`X-Content-Type-Options`·`Referrer-Policy`·`Permissions-Policy` 헤더가 없다고 보고됐다. 로컬 설정만으로 운영 반영을 완료했다고 할 수 없으므로 이 항목은 미해결이다.
4. 환경 변수·배포 자격증명의 실제 접근 권한과 과거 Git 기록의 노출 여부는 별도 확인한다. `.gitignore`와 패턴 검사는 이미 유출된 값을 폐기하거나 모든 유출을 검출하는 수단이 아니다.

이번 개인 브라우저 설정 범위에 로그인·DB·별도 암호화 계층을 추가할 근거는 없다. 가족 공유나 기기 간 동기화가 실제 범위가 될 때 인증·소유권·서버 저장의 거래와 제약을 설계한다. 검토 통과는 이 범위에서 확인한 보호와 실행한 검사만을 뜻하며 모든 위험이 없다는 보증은 아니다.
